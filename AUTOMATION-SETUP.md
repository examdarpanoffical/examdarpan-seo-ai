# Exam Darpan: Automatic Official-Source Monitoring

This add-on monitors Rajasthan official sources, creates a **Firestore draft** using Gemini, and saves a Firestore draft. It does **not publish automatically**. A separate GitHub Action shares only posts that you actually publish.

## Sources included

- RSSB — https://rssb.rajasthan.gov.in/
- RPSC — https://rpsc.rajasthan.gov.in/
- Rajasthan School Education — https://education.rajasthan.gov.in/
- RBSE — https://rajeduboard.rajasthan.gov.in/main.asp
- Rajasthan Police recruitment/results — https://police.rajasthan.gov.in/portal/RecruitmentsResults
- Rajasthan Recruitment Portal — https://recruitment.rajasthan.gov.in/

## Important architecture choice

The scheduler is GitHub Actions, not Firebase scheduled functions. This avoids requiring Firebase Functions/Secret Manager for the monitoring layer. Your existing Firebase Hosting + Firestore site remains the CMS.

The monitor uses a Firebase service-account secret to write drafts to Firestore and a Gemini API key only inside GitHub Actions. **Never put either secret into `public/` or frontend JavaScript.**

## One-time setup

1. Put this project in a GitHub repository.
2. In Firebase Console, create/download a service-account JSON from Project settings → Service accounts.
3. In GitHub: Settings → Secrets and variables → Actions → New repository secret.
4. Add these four secrets:

- `FIREBASE_SERVICE_ACCOUNT_JSON` = the complete service-account JSON as one secret value.
- `GEMINI_API_KEY` = your Gemini Developer API key.
- `TELEGRAM_BOT_TOKEN` = token from BotFather.
- `TELEGRAM_CHAT_ID` = your Telegram channel/chat ID.

5. Add the bot as an administrator of the Telegram channel with permission to post messages.
6. Run **Actions → Exam Darpan Official Source Monitor → Run workflow** once manually.
7. Check Firestore collection `posts`. New items should have `status: draft` and `autoGenerated: true`.
8. Review the draft in Admin and click **Publish**.
9. The separate `telegram-publisher.yml` workflow checks published posts every 5 minutes and sends each one to Telegram once.

## Telegram chat ID

For a channel, the easiest method is to add the bot as an admin, post a test message in the channel, then use Telegram's Bot API `getUpdates` or a small temporary bot script to obtain the channel chat ID. Do not paste the bot token into this repository.

## First-run safety

The workflow currently has `BOOTSTRAP_SKIP_EXISTING=false`, so the first manual run can create drafts for discovered current links. If you want a quiet baseline run first, temporarily change it to `true`, run once, then change it back to `false`.

## What happens after setup

Official page → new link detected → source text/PDF extracted → Gemini draft → Firestore `posts` draft → you review/edit → Publish in Admin → Telegram publisher shares the live article URL.

## Limitations

This is intentionally a conservative v1. Some government sites change their HTML frequently or load notices dynamically. If a source changes layout, that source may need a parser update. The monitor records errors in `monitor_seen` so failures can be diagnosed instead of silently publishing bad information.
